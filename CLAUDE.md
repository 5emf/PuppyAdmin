# Puppy Admin: notes for future sessions

## Rules from the owner
- **Every game gets its own generated images.** Each mini game in the Games window ships a sprite sheet in `assets/games/` (64 px cells, drawn in code with Pillow at 4x and downsampled). That covers the moving pieces (`actors` + `spriteCell`) and the grid tiles (`cellSprite`): walls, blocks, shields, food, and so on. Coloured squares are only the fallback while the sheet downloads. When you add a game, make its sheet in the same change.
- When a sheet changes, give it a new file name (for example `_v2`). The script caches images by URL on the player's device.
- Games are original. Genres are fine (snake, falling blocks, maze chase, fixed shooter); recreations of a specific game's name, characters or look are not.
- Commercial game files (ROMs, id Software WADs) never go in this public repo. Players put them in their executor folder (`PuppyAdmin/roms`, `PuppyAdmin/gba`, `PuppyAdmin/doom`). The same goes for Nintendo's GBA BIOS: the repo ships the free Cult-of-GBA BIOS (MIT) in `assets/gba`. Freely licensed data such as Freedoom is fine.

## How the script is put together
- `PuppyAdmin.lua` is the loadstring entry. Bump `SCRIPT_BUILD` with every change; a newer build replaces a running older one.
- Large parts are separate, version-named files that are downloaded and cached on first use: `engine/engine-<hash>.lua` (reanimation and movement), `emu/gameboy-<hash>.lua`, `emu/gba-<hash>.lua` and `emu/doom-<hash>.lua`. Their size and version are pinned in the main script.
- GBA core: hand-written Luau (ARM7TDMI interpreter, scanline video, DMA, timers, SRAM / Flash / EEPROM saves, sound: tone channels + DirectSound FIFOs mixed to 16384 Hz mono PCM). Roblox cannot stream raw audio, so `UIAPI.newPcmStream` cuts the PCM into 0.25 s files that play back to back with crossfades. It first loads a silent test file of each type side by side (WAV, FLAC, or MPEG-1 Layer II saved as `.mp3`, encoded in `gba_pcm.luau` with the ISO analysis window) and uses the first one Roblox loads. Sources live in the scratchpad (`gba/core_cpu.luau`, `core_ppu.luau`, `core_apu.luau`, `gba_zip.luau`, `gba_pcm.luau`); `gba/build_module.py` writes `emu/gba-<hash>.lua` and updates `UIAPI.GBA_MODULE`. jsmolka's gba-tests (MIT) all pass; keep them passing.
- Doom sound: the engine passes sound calls to the host (`opts.sound` in the Doom module). Freedoom Phase 1's effects (`sfx_v<N>.pak`) and music (`music_v<N>/`) are pre-rendered mp3 in `assets/doom/freedoom1`, made by the scratchpad script `make_doom_audio.py`. Bump the `_v` names in `UIAPI.DOOM_SOUND` when they change.
- UI: Settings is one window with three scrolling tabs (`UIAPI.settingsTab(name)`): General (prefixes, UI key, intro, anti-AFK, nametags, Alts, tag-sync token), Look (theme presets/colors, background image, font, text size, cursor), Windows (a button for every window). The command directory (`help`) has category tabs from `UIAPI.CMD_CATEGORIES` / `UIAPI.cmdCategory` (explicit lists, then the engine's PUP_MOVE / PUP_PERF groups, then words in the help line) and is rebuilt on open (`UIAPI.fillHelp`). Clicking a row that opens a window opens it (`UIAPI.CMD_OPENS`: a panel key shows the panel without the command's side effects; true runs the command); any other row puts the command in the command bar. Add new window commands to `CMD_OPENS` and the Windows tab list.
- Cursor (`UIAPI.Cursor`, Settings > Look, `cursor` command): Default, Glove, Light, Keyblade (owner-supplied images in `assets/cursors/*_v1.png`, hotspot fractions in `Cursor.BUILTIN`) or Custom (image id/URL, top-left hotspot). An ImageLabel in its own top ScreenGui follows `GetMouseLocation()` and Roblox's pointer is hidden; hidden again in LockCenter (first person / shift lock). `Cfg.cursor`, `Cfg.cursorImage`, `Cfg.cursorSize`.
- The main chunk sits at Lua's 200-local limit. Put new code in functions or `do` blocks, or on tables such as `UIAPI.*`, instead of adding top-level locals.
- Check that it parses with `luac5.4 -p` (on a copy with the engine stubbed when needed), and compare free names and global writes against the previous version.

## Puppy Companion (desktop app, `companion/`)
- Windows app in Python 3 with only the standard library (Tkinter, ctypes); built into `PuppyCompanion.exe` with PyInstaller by `.github/workflows/companion.yml` (tests, build, then the built program's `--selftest`). Keep the tests passing: `python -m unittest discover -s tests` from `companion/` (window tests need Tk and a display; under Linux use `xvfb-run`).
- Login cookies: encrypted with DPAPI (`secure.py`), never logged (`redact.py`), never written to the executor workspace, and sent only to roblox.com. Do not add any other destination for them.
- Everything that depends on Roblox's launch protocol or single-window lock is in `launch.py`; the web requests are in `roblox.py`. Both are unverified against live Roblox until the owner reports back.
- Fishstrap / Bloxstrap: `launch.detect_bootstrapper()` reads the `roblox-player` URI handler from the registry; launches already go through whichever bootstrapper is installed. The `bootstrapper_multi` setting + its Settings checkbox make the companion release its own mutex so Fishstrap/Bloxstrap manages the windows. Weak-PC help (Surface Book) is mostly the in-game low-power alt mode (`Cfg.altLite`) plus a longer launch delay.
- Puppy Admin side: `UIAPI.companionStart` writes `PuppyAdmin/companion/<UserId>.json` every 10 s (online false on shutdown); the app writes `PuppyAdmin/companion/roster.json` (main and alt user IDs and names). Keep the field names in step with `workspace.py`.
- Self-update (`update.py`): `resolve_ref` asks api.github.com for the branch's commit SHA and the manifest plus every file are read from that one commit (raw branch URLs are CDN-cached for minutes, which mixed old and new files right after a push and failed the checksum). Falls back to the branch name if the API is unreachable. The same check reads `SCRIPT_BUILD` from `PuppyAdmin.lua` and the Accounts list flags windows whose status `build` is older ("old Puppy Admin, execute again"): in-game changes arrive by re-executing Puppy Admin, not through the companion.
- Manage tab (`manage.py`, `ManageTab`): per-account settings in `Account.prefs` (`store.PREF_DEFAULTS` / `clean_prefs`: lite, fps, mute, vc_auto, launch_order, extra_delay, auto_rejoin, notes) and `Account.group`. `workspace.write_roster` puts only lite/mute/vcAuto/fps (set ones) into each alt's `prefs` in roster.json; `Alts.loadRoster` / `Alts.myPrefs()` / `Alts.liteOn()` in PuppyAdmin.lua apply them over the global switches. Launch order + extra delay feed the launch queue; `CompanionApp.auto_rejoin_tick` relaunches dropped alts into the main's server (45 s grace, 120 s between tries, 3 per 10 min). Launch tab has "Launch group".
- Roblox account calls (`roblox.ENDPOINTS`: profile, display name, About, user-settings privacy, sign out everywhere, headshot) are from memory, not checked against Roblox docs (roblox.com was unreachable from the build container). Privacy dropdowns come from Roblox's own response (`parse_user_settings`), never hard-coded values. The headshot request and image download carry no cookie. Sign out everywhere saves the new cookie from Set-Cookie only after `authenticated_user` confirms the same user id.
- New companion modules may only import stdlib modules the frozen exe already bundles (an update to an old exe has no new modules); check `grep -h ^import puppy_companion/*.py`.
- Fonts: the Kingdom Hearts style fonts (KH Menu with Bold/Italic/BoldItalic, KH Gummi, KH Data, KH Title, KH Scala, KH Scala Script, Kingdom Hearts) were supplied by the owner as woff2 and converted to TrueType outlines (fontTools, CFF -> glyf). They live in `assets/fonts` (Puppy Admin: `UIFont.CUSTOM`, a family JSON with one face per weight/style) and in `companion/puppy_companion/fonts` (`fonts.py`: loaded per process with `AddFontResourceExW(FR_PRIVATE)`, Settings "App font"; bundled into the exe with PyInstaller `--add-data`, and they also travel in payload.json for updates).
- The icon is drawn by `companion/tools/make_icon.py` (writes the .ico and `puppy_companion/icon_data.py`).
- Alt control (`UIAPI.altsSetup` in `PuppyAdmin.lua`): the main writes `PuppyAdmin/companion/altcmd.json` (`action` cmd/stop, `cmd`, `params`, `target`, `center`, and either `layers` for `form` or `ids` for other commands); alts on the same PC poll it (every 0.25 s) and either place their own characters each frame (pin), walk (`Humanoid:MoveTo`), or do a one-shot. Only alts in `roster.json` with a fresh status file get a place.
  - One unified engine: `Alts.SPECS` is the command table; `Alts.BEHAV` holds the per-frame offset functions; `Alts.follow` (formations) and `Alts.beginCmd`/`Alts.runOnce` (everything else) feed one Heartbeat `step`. Formations (`form`) are unchanged and still original (wings, halo, ring, star, spiral, tower, wall, trail, scatter). Keep all of it original; do not recreate another game's character/mode or its named references.
  - Commands are namespaced under the `alt` word (`.alt circle bob`, `.alt orbit3`, `.alt say hi`, `.alt stop`), so they never clobber the player's own `.noclip` / `.fly` / `.speed`. `Alts.resolveName` maps `orbit3`→(orbit, style 3) etc. The `bang`/`fbang`/`mbang` commands are intentionally NOT implemented (sexual-harassment behaviour) — do not add them.
  - One window, three tabs (`UIAPI.buildAltsPanel`): Accounts (roster + low-power / voice-ban toggles + stop), Formations (shape dropdown + sliders/switches + start/stop), Commands (target box, chat box, a curated button set; the full list is still available via `alt <name>` in chat). `altcmds` / `H.altcmds` just opens this window on the Commands tab (there is no separate command-board panel any more). The Settings "Alts" button shows live status (`UIAPI.altsButtonStatus`).
  - One-shot commands (`mode == "once"`: say, jump, dance, emote, equip, rest, …) are fire-and-forget — `Alts.run` writes the command once and does NOT set `Alts.active`, so the main never resends/re-fires them (that was the "say spams and never stops" bug). `spam` is one-shot too but keeps going via its own loop until a new command or `stop`. Continuous commands (pin/walk/idle) still set `Alts.active` and resend.
  - Target resolution (`Alts.run`) trims the typed name before `resolveTargets` (a trailing space, common from the box or phone keyboards, otherwise gives a false "name a player"), accepts a raw UserId, and gives a precise message.
  - Low-power mode `Cfg.altLite` (default on): alts cap their own FPS (`Cfg.altLiteFps`, 30) with `setfpscap`, throttle the pin loop to ~30 Hz, and `Alts.applyLowGraphics()` (once per alt) drops render quality to the lowest and kills shadows/fog/post effects — this is what makes many windows viable on weak machines (e.g. a 2014 Surface Book). The main is never FPS-capped or dimmed.
  - Alts are always muted (`Alts.muteAudio`, independent of low-power): `MasterVolume = 0` and `VoiceChatInternal:SubscribePause` on other players, so an alt hears neither game audio nor other players. `Alts.applyAltClientSettings` (mute always + low graphics if `Cfg.altLite`) runs once per alt from the watcher.
  - Limbs, two Formations switches. `Cfg.altForm.limbs` "Separate limbs (game's ragdoll, no death)": `Alts.shatter(st)` is a small state machine per body: `settle` (a fresh or respawned body waits `Alts.SETTLE` = 2 s and until `isnetworkowner(root)` when the executor has it; separating at once after a respawn left parts the client could not move — the "alts stop moving after respawn" bug), then `ragdoll` (fires the game's ragdoll remote from `Alts.ragdollRemote`, the same games / names / args as `get_game_ragdoll_info` in the reanimation engine, and waits up to `Alts.RAGDOLL_WAIT` for the server to disable the Motor6Ds), then `free` (ragdoll constraints switched off locally — the owner simulates them, and constraints do not merge parts, so every limb replicates on its own — and `step` drives each part with CFrame + the netless push `SETTINGS.VelocityY`). No ragdoll: `whole` (bodies tumble) unless `Cfg.altForm.limbsDeath` "No ragdoll? Let alts DIE to separate" is on, then the alt dies with `BreakJointsOnDeath` (server breaks the joints) and the parts are driven until the respawn, after which the new body settles and separates again. `Alts.reassemble` re-enables the constraints and fires the ragdoll remote off for a ragdolled body. The owner asked that separating never kill without the death switch. Client-side Motor6D changes or welds to client-made anchored parts only show on the alt's own screen; do not go back to them. Unverified in live games.
  - VC-ban: `Alts.voiceUnavailable` uses `VoiceChatService:IsVoiceEnabledForUserIdAsync` (best effort; false also means "voice never enabled", so confirm on a known-banned account). `Cfg.altVcAuto` (default on) makes alts run the existing `VCB.run` bypass by themselves; `.alt vcban` / the board button forces it. Compatible with the `antivcban` panel (same `VCB`).
  - Whitelisted players (`Cfg.altWhitelist`, set with `.alt whitelist <player>`) may drive the alts, but only through the `alt` word in chat (`Alts.relay`), never the main's other commands.
  - Animation ids in `Alts.EMOTES`/`Alts.DANCE` are Roblox's public default R15 emote assets (confirm/override per rig; R6 differs); `Alts.rizzAnim` is unset (needs an id you own).
  - Test with `lua5.4 tools/test_alts.lua PuppyAdmin.lua` (shape math for 1-12 alts, command round trip incl. target/once/numbered commands, low-power, the window and the command board).
